## [§](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/index.html\#migrating-from-v23-to-v25) Migrating from v23 to v25

1. [`Events::all()` return type changed from `Vec<(Address, Vec<Val>, Val)>` to `ContractEvents`](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/v25_event_testing/index.html "mod soroban_sdk::_migrating::v25_event_testing").
The new type supports the old comparison format, so most code will continue to work.
New methods like `filter_by_contract()` and XDR comparison via `to_xdr()` are now available.

2. [BN254 (alt\_bn128) elliptic curve support added](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/v25_bn254/index.html "mod soroban_sdk::_migrating::v25_bn254").
Access via `env.crypto().bn254()` for G1/G2 point operations and pairing checks.

3. [Poseidon and Poseidon2 permutation functions added](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/v25_poseidon/index.html "mod soroban_sdk::_migrating::v25_poseidon").
Available via `CryptoHazmat` under the `hazmat-crypto` feature for advanced
cryptographic use cases.

4. [`contracttrait` macro added for reusable contract interfaces](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/v25_contracttrait/index.html "mod soroban_sdk::_migrating::v25_contracttrait").
Define traits with default implementations using `#[contracttrait]`, then implement them
in contracts using `#[contractimpl(contracttrait)]`.

5. [Resource limit enforcement enabled by default in tests](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/v25_resource_limits/index.html "mod soroban_sdk::_migrating::v25_resource_limits").
`Env::default()` now enforces Mainnet resource limits for contract invocations.
Tests will fail if limits are exceeded. This provides early warning of contracts that
may be too resource-heavy for Mainnet. If you see test failures after upgrading,
use `env.cost_estimate().disable_resource_limits()` to opt-out while optimizing.


## [§](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/index.html\#migrating-from-v22-to-v23) Migrating from v22 to v23

1. [`contractevent` replaces `Events::publish`](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/v23_contractevent/index.html "mod soroban_sdk::_migrating::v23_contractevent")

2. \[`MuxedAddress` replaces `Address` as the `to` of the `TokenInterface::transfer`\].
This change concerns `soroban-token-sdk` and is documented in detail in
`soroban-token-sdk` crate migration guide.

3. [Accessing archived persistent entries in tests no longer results in a panic](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/v23_archived_testing/index.html "mod soroban_sdk::_migrating::v23_archived_testing"),
automatic restoration is emulated instead. Note, that instance storage is a
persistent entry as well.


## [§](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/index.html\#migrating-from-v21-to-v22) Migrating from v21 to v22

1. [`Env::register`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register "method soroban_sdk::Env::register") and [`Env::register_at`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_at "method soroban_sdk::Env::register_at") replace [`Env::register_contract`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_contract "method soroban_sdk::Env::register_contract") and [`Env::register_contract_wasm`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_contract_wasm "method soroban_sdk::Env::register_contract_wasm").

[`register`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register "method soroban_sdk::Env::register") registers both native contracts previously registered with
[`register_contract`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_contract "method soroban_sdk::Env::register_contract") and Wasm contracts previously registered with
[`register_contract_wasm`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_contract_wasm "method soroban_sdk::Env::register_contract_wasm"). It accepts a tuple that is passed to the
contracts constructor. Pass `()` if the contract has no constructor.



```
use soroban_sdk::{contract, contractimpl, Env};

#[contract]
pub struct Contract;

#[contractimpl]
impl Contract {
       // ..
}

#[test]
fn test() {
       let env = Env::default();
       let address = env.register(
           Contract,  // 👈 👀 The contract being registered, or a Wasm `&[u8]`.
           (),        // 👈 👀 The constructor arguments, or ().
       );
       // ..
}
```



[`register_at`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_at "method soroban_sdk::Env::register_at") registers both native contracts previously registered
with [`register_contract`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_contract "method soroban_sdk::Env::register_contract") and Wasm contracts previously registered with
[`register_contract_wasm`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.register_contract_wasm "method soroban_sdk::Env::register_contract_wasm"), and allows setting the address that the
contract is registered at. It accepts a tuple that is passed to the
contracts constructor. Pass `()` if the contract has no constructor.



```
use soroban_sdk::{contract, contractimpl, Env, Address, testutils::Address as _};

#[contract]
pub struct Contract;

#[contractimpl]
impl Contract {
       // ..
}

#[test]
fn test() {
       let env = Env::default();
       let address = Address::generate(&env);
       env.register_at(
           &address,   // 👈 👀 The address to register the contract at.
           Contract,  // 👈 👀 The contract being registered, or a Wasm `&[u8]`.
           (),        // 👈 👀 The constructor arguments, or ().
       );
       // ..
}
```

2. [`DeployerWithAddress::deploy_v2`](https://docs.rs/soroban-sdk/latest/soroban_sdk/deploy/struct.DeployerWithAddress.html#method.deploy_v2 "method soroban_sdk::deploy::DeployerWithAddress::deploy_v2") replaces [`DeployerWithAddress::deploy`](https://docs.rs/soroban-sdk/latest/soroban_sdk/deploy/struct.DeployerWithAddress.html#method.deploy "method soroban_sdk::deploy::DeployerWithAddress::deploy").

[`deploy_v2`](https://docs.rs/soroban-sdk/latest/soroban_sdk/deploy/struct.DeployerWithAddress.html#method.deploy_v2 "method soroban_sdk::deploy::DeployerWithAddress::deploy_v2") is the same as [`deploy`](https://docs.rs/soroban-sdk/latest/soroban_sdk/deploy/struct.DeployerWithAddress.html#method.deploy "method soroban_sdk::deploy::DeployerWithAddress::deploy"), except it accepts a list of
arguments to be passed to the contracts constructor that will be called
when it is deployed. For deploying existing contracts that do not have
constructors, pass `()`.



```
use soroban_sdk::{contract, contractimpl, BytesN, Env};

#[contract]
pub struct Contract;

#[contractimpl]
impl Contract {
       pub fn exec(env: Env, wasm_hash: BytesN<32>) {
           let salt = [0u8; 32];
           let deployer = env.deployer().with_current_contract(salt);
           // Pass `()` for contracts that have no contstructor, or have a
           // constructor and require no arguments. Pass arguments in a
           // tuple if any required.
           let contract_address = deployer.deploy_v2(wasm_hash, ());
       }
}

#[test]

       // Upload the contract code before deploying its instance.

3. Deprecated [`fuzz_catch_panic`](https://docs.rs/soroban-sdk/latest/soroban_sdk/testutils/arbitrary/fn.fuzz_catch_panic.html "fn soroban_sdk::testutils::arbitrary::fuzz_catch_panic"). Use [`Env::try_invoke_contract`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.Env.html#method.try_invoke_contract "method soroban_sdk::Env::try_invoke_contract") and the `try_` client functions instead.

The `fuzz_catch_panic` function could be used in fuzz tests to catch a contract panic. Improved behavior can be found by invoking a contract with the `try_` variant of the invoke function contract clients.



```
use libfuzzer_sys::fuzz_target;
use soroban_sdk::{contract, contracterror, contractimpl, Env, testutils::arbitrary::*};

#[contract]
pub struct Contract;

#[contracterror]
#[derive(Debug, PartialEq)]
pub enum Error {
       Overflow = 1,
}

#[contractimpl]
impl Contract {
       pub fn add(x: u32, y: u32) -> Result<u32, Error> {
           x.checked_add(y).ok_or(Error::Overflow)
       }
}

#[derive(Arbitrary, Debug)]
pub struct Input {
       pub x: u32,
       pub y: u32,
}

fuzz_target!(|input: Input| {
       let env = Env::default();
       let id = env.register(Contract, ());
       let client = ContractClient::new(&env, &id);

       let result = client.try_add(&input.x, &input.y);
       match result {
           // Returned if the function succeeds, and the value returned is
           // the type expected.
           Ok(Ok(_)) => {}
           // Returned if the function succeeds, and the value returned is
           // NOT the type expected.
           Ok(Err(_)) => panic!("unexpected type"),
           // Returned if the function fails, and the error returned is
           // recognised as part of the contract errors enum.
           Err(Ok(_)) => {}
           // Returned if the function fails, and the error returned is NOT
           // recognised, or the contract panic'd.
           Err(Err(_)) => panic!("unexpected error"),
       }
});
```

4. Events in test snapshots are now reduced to only contract events and system events. Diagnostic events will no longer appear in test snapshots.

This will cause all test snapshot JSON files generated by the SDK to change when upgrading to this major version of the SDK. The change should be isolated to events and should omit only diagnostic events.


## [§](https://docs.rs/soroban-sdk/latest/soroban_sdk/_migrating/index.html\#migrating-from-v20-to-v21) Migrating from v20 to v21

1. [`CustomAccountInterface::__check_auth`](https://docs.rs/soroban-sdk/latest/soroban_sdk/auth/trait.CustomAccountInterface.html#tymethod.__check_auth "associated function soroban_sdk::auth::CustomAccountInterface::__check_auth") function `signature_payload` parameter changes from type [`BytesN<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.BytesN.html "struct soroban_sdk::BytesN") to [`Hash<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/crypto/struct.Hash.html "struct soroban_sdk::crypto::Hash").

The two types are interchangeable. [`Hash<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/crypto/struct.Hash.html "struct soroban_sdk::crypto::Hash") contains a [`BytesN<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.BytesN.html "struct soroban_sdk::BytesN") and can only be constructed in contexts where the value has been generated by a secure cryptographic function.

To convert from a [`Hash<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/crypto/struct.Hash.html "struct soroban_sdk::crypto::Hash") to a [`BytesN<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.BytesN.html "struct soroban_sdk::BytesN"), use [`Hash<32>::to_bytes`](https://docs.rs/soroban-sdk/latest/soroban_sdk/crypto/struct.Hash.html#method.to_bytes "method soroban_sdk::crypto::Hash::to_bytes") or [`Into::into`](https://doc.rust-lang.org/nightly/core/convert/trait.Into.html#tymethod.into "method core::convert::Into::into").

Current implementations of the interface will see a build error, and should change [`BytesN<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/struct.BytesN.html "struct soroban_sdk::BytesN") to [`Hash<32>`](https://docs.rs/soroban-sdk/latest/soroban_sdk/crypto/struct.Hash.html "struct soroban_sdk::crypto::Hash").



```
